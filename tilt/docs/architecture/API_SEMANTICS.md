# Verified Lichess export semantics

Live smoke performed 2026-11-08 using the public user `DrNykterstein`: 20 unique standard games, plus a second export of one of those games with `pgnInJson=true` for direct PGN/NDJSON comparison. No monthly dump was downloaded. Responses and derived data remain only under git-ignored `tilt/data/`; no real game records are fixtures.

Observed: 5 blitz / 15 bullet games, 1,633 plies, 1,538 centipawn entries, 89 mate entries, and 6 plies without source evals. The first-move clock states frequently read 60.03 or 180.03 seconds rather than the nominal initial time; compression explains that quantisation. All sampled controls have zero increment; nonzero-increment handling was checked against repository code and synthetic tests, not a live increment sample.

| API field | Semantics and normalization | Evidence |
|---|---|---|
| `createdAt` | UTC epoch milliseconds for creation, used as a conservative game-start timestamp. API `since` filters this field; the ordinary Mongo path is inclusive, while the perf-filtered search path rechecks it with strict `isAfter`. Resume offsets account for that difference; `until` is exclusive on both paths: `Game.scala` passes it to `GameApiV2.ByUserConfig`; Mongo uses `Query.createdBetween` → `db.dsl.dateBetween` with `.lt(until)` (`lila/modules/db/src/main/dsl.scala:178–181`); search rechecks `GameApiV2.inCreatedAtRange` with `isBefore` (`GameApiV2.scala:454–455`). Backfill therefore sends the oldest stored createdAt unchanged, with no minus-one offset. | `lila/modules/api/src/main/GameApiV2.scala`; API docs. |
| `lastMoveAt` | UTC epoch ms of last move; **not** a universal game-end timestamp. Finishing by resignation/draw acceptance doesn't change `movedAt`. Retained separately. | `lila/modules/game/src/main/Game.scala` `applyMove` and `finish`; `lila/modules/game/src/main/GameRepo.scala` `finish`. |
| `clock.initial`, `clock.increment` | Nominal seconds, not centiseconds; player-specific berserk may differ. | `GameApiV2.scala` serializes `limitSeconds` / `incrementSeconds`. |
| `clocks[i]` | Centiseconds of the mover's remaining clock after played ply `i+1`, alternating from the starting colour. Divide by 100. These are not durations. | Direct comparison to `[%clk]` in the PGN: maximum difference 0.49 seconds because PGN clocks round to whole seconds. `lila/modules/core/src/main/game/data.scala` `ClockHistory.bothClockStates`. |
| Clock length | Can be **plies+1** when a game ends between moves: the final item is the stopped active player's clock, not another move. Mate/automatic draw on a move has no extra item and no increment on that last move. | 14/20 sampled games had one extra clock entry; 6/20 ended on a move. `GameExt.finish`, `computeMoveTimes` and `scalachess/core/src/main/scala/Clock.scala`. |
| First clocks | For ordinary standard games both first moves are unclocked and receive no increment: clock starts after the second ply. Feature think-time is **missing**, with `unclocked_first_move=true`, rather than treating unmeasured time as instant play. | `scalachess/core/src/main/scala/Game.scala` `applyClock`; `Clock.step` when timer=None; Lichess `computeMoveTimes` starts each colour with a conventional zero. |
| `analysis[i].eval` | White-POV **centipawns after ply i+1**. Not pawns, not mover POV, and no initial-position entry. Missing stays missing. | All centipawn scores in the compared PGN match exactly after multiplying PGN `[%eval]` pawn values by 100. `lila/modules/analyse/src/main/JsonView.scala`. |
| `analysis[i].mate` | Signed moves-to-mate, normally White POV, mutually exclusive with cp. **0 is special**: the side to move is mated; infer winner from board turn, not from the sign of zero. Normalized moves retain raw mate=0; features resolve terminal checkmate to the White winner's ±1000 cp ceiling. | 89 live mate entries; `lila/modules/tree/src/main/Info.scala` `exportMate` and `scalachess/.../eval.scala` `WhiteScore.exportMate`. Local synthetic tests cover both mate signs/terminal zero. |
| `analysis[i].best` | UCI alternative to the just-played move, when present; don't blindly shift it to the next position. The analysis `Info` is after the move; its `best` is attached for advice about that move. | `lila/modules/tree/src/main/Advice.scala` `makeComment`, `Info.scala`, `analyse/JsonView.scala`. All 221 observed `best` moves were legal before the indexed move, and none after it. Missing best moves require local analysis; don't interpret missing as best play. |
| `division.middle`, `.end` | Board-index/ply boundaries. Runtime `Position.playBoards` includes the initial board plus every after-move board. Feature phase describes the **before-move** board at zero-based index ply−1. Division fields can be absent. | Exact port reproduced **20/20** observed divisions. `scalachess/core/src/main/scala/Divider.scala`, `CanPlay.scala`, `lila/modules/game/src/main/Divider.scala`. |
| `players.*.analysis.accuracy` | Rounded game accuracy, not an eval or tilt label. Recomputed as volatility-weighted mean/harmonic mean from the source formula. | Using API evals and the Lichess legacy initial +15 cp, one compared game yielded White 83.711432 / Black 79.070937, matching API 84 / 79 after rounding. |

End-time policy: terminal-move games use `lastMoveAt` with a 20 ms safety margin. With a stopped extra clock, estimate `lastMoveAt + max(0, previous_active_clock − stopped_active_clock)`; normalize centiseconds to milliseconds, and add **1,000 ms** to obtain `end_upper_ms`. The compression codec rounds nonfinal values ≥10 s in 8-centisecond buckets (at most 4 cs error); the final value retains its low bits. The one-second margin exceeds that quantisation and timestamp resolution. It is a conservative bound under normal clock-history operation, not a wall-clock reconstruction of network latency. For missing clocks, unexpected history shape, or unreconstructible ends, use the time the finished response was observed as an upper bound; do not substitute lastMoveAt. Dump end headers get a one-second resolution margin; absent end headers produce no usable historical end bound. No end is fabricated by summing think times because lag compensation and added time break that equivalence.

Clock features use own previous clock minus current clock plus the applicable increment; omit increment on the move ending a game. Observed first own clock is the denominator for remaining fraction, including berserk controls. A mismatch between nominal and observed initial time without explicit berserk metadata makes subsequent think-times missing when the nominal increment is nonzero (zero remains known): the API can omit berserk flags and nominal increment may be wrong. Added time/takebacks can break deltas; negative spent time below −0.1 s is flagged and missing, not silently made zero. Small negative quantisation errors clamp to zero. A dump draw on a threefold/50-move claim position may not reveal whether the final move received increment; that last move's increment/time stays missing instead of guessing. Export clock histories can contain source errors; `end_kind` preserves the distinction between estimates and observed bounds.

Formula distinctions are deliberate: `winningChances.ts` clamps ordinary cp to ±1000 and treats mate by distance; server `WinPercent` uses the ±1000 ceiling for mate. Server `Advice.scala` cp judgement thresholds are inclusive `>= .1/.2/.3` in raw winning-chance difference (range 0–2), whereas `liveAnnotate.ts` uses strict `>` and suppresses the best move. Features use the server thresholds and mate-advice rules; the played checkmating move is good. Move accuracy uses **percentage-point** WinPercent loss, the uncertainty bonus +1, and [0,100] clamping. Game accuracy uses the mean of a volatility-weighted mean and harmonic mean, not arithmetic mean move accuracy. The conventional initial cp=15 is used only for the untouched standard starting position if no engine eval exists, with explicit `lichess_legacy_initial` provenance.
